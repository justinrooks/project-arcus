## Decision and discovery boundary

Keep correctness checks in the default `SkyAware_Tests` regression plan; put repeated timing and measurement artifacts in an optional performance plan using the existing `SkyAwareTests` target. Split mixed entry points before excluding them. Preserve all current fixture dimensions and meaningful assertions; neither a measurement filename nor elapsed time establishes lane membership.

Discovery covered all 91 Swift files in `Tests/UnitTests`, plus a `Tests/**/*.swift` cross-check for XCTest owners, metric APIs, wall/CPU clocks, repeated timing, attachments, environment gates, renderers, and file exports. Six timing entry points occur in four files: five are mixed and one is performance-only. Only the two map measurement classes subclass `XCTestCase` in the unit directory. Only scene warming calls XCTest's `measure(metrics:options:)`; accepted-update tests record manual clock samples and XCTest attachments, not native XCTest metric recordings. Other matches include Foundation weather `Measurement` values, domain evidence DTOs, timeout/budget clocks, and persistence fixtures; these are correctness work. UI launch metrics and screenshot attachments are outside this unit inventory and remain unchanged.

Follow the [Unit CI 01 baseline](unit-ci-01-baseline.md) for Cloud evidence and unresolved failures. Its 1,480 logical cases and 1,699 expanded Cloud executions are historical observations, not required future constants. Classification is independent of the diagnostic-collection hypothesis; no saving or regression pass follows from this source inventory.

## Shared setup, ownership and system assumptions

- Projection helpers are private to the existing suite/file. `TestStore.container` ([TestStore.swift](../../Tests/UnitTests/TestStore.swift):4–12) creates a fresh in-memory `ModelContainer` per call on `MainActor`; each population/sample saves its own seeded context. `HomeProjectionStore` actor calls are awaited, fetched model objects stay on the main actor, and conversion uses the same container's records. Preserve ownership and freshness; never share a context across actors or cache one seeded store globally to avoid duplicate setup. These are in-memory persistence semantics, not migration/reopen coverage.
- Projection scaling is `.serialized` and `@MainActor`; both XCTest map classes and the Swift Testing accepted-update suite are `@MainActor`. Hatch tests have no suite serialization annotation. Retain these boundaries. Other serialized suites are correctness owners, not candidates for exclusion or wider serialization. Suite-local serialization does not isolate process-global state from other suites.
- Keep map fixtures, counted-provider actors, `ScopedMapHarness`, `CountedMapPlanner` and `IndexedReloadGate` file-local. Extract common untimed operations within their current owners; the R checks and P loops may each call them with their own fresh harness. Two lane invocations necessarily repeat setup; avoid copying fixture definitions or moving helpers across files just to eliminate that cost. The nine-scenario method's intentional within-test reuse is distinct from cross-test sharing.
- Hatch timing and pixel/stripe correctness share `hatchRenderer`/`hatchContext`; leave them in place. Pixel tests cover 12 angle/intensity combinations × 5 zooms, tile edges, holes and visibility threshold; `hatchLineSelection` covers five angles and verifies every intersecting legacy stripe, a bounded line count and empty off-polygon selection. These operation/pixel assertions remain regression even when computationally substantial.
- Scene report variables `MAP_SCENE_MEASUREMENT_SOURCE`, `SIMULATOR_MODEL_IDENTIFIER` and `SIMULATOR_RUNTIME_VERSION` label output; they do not gate execution. Manual wall/CPU samples depend on simulator/host contention. Do not add fixed duration thresholds, retries, isolation changes or a new target.
- Complete Today evidence uses `UI_TESTS_STATIC_HOME=1`, `MainActor`, a connected `UIWindowScene`, temporary key-window changes and a 100 ms layout wait for accessibility variants. It writes 20 PNGs under `/private/tmp/673-awareness`. The other Today tests write fixed `/private/tmp/486-*.png`, `/private/tmp/620-warning-hero-*.png` and `/private/tmp/692-today-support-chevrons` paths. These exports are not XCResult attachments and can overwrite earlier evidence. Preserve current behavior here; copy opt-in outputs per run when collecting evidence. Do not mutate the environment in a concurrent suite to enable the gate. ImageRenderer/PNG success does not establish native controls or physical-device accessibility.
- Onboarding's renderer is a correctness helper for contrast/color assertions, not an exported benchmark. File writes elsewhere (for example `HomeProjectionStoreTests`, downloader/cache/queue/snapshot fixtures) exercise storage behavior. Deadline polling and `ContinuousClock` use in HTTP, ingestion, location, alert, reload and background tests synchronize work or assert budget/cancellation semantics; a clock alone is not a performance measurement.

## Selection contract and minimum follow-up changes

Current [SkyAware_Tests.xctestplan](../../Tests/SkyAware_Tests.xctestplan) selects the whole parallelizable `SkyAwareTests` target with no test filters; diagnostics are Never following #764. The shared scheme makes it default. [run_test_lane.sh](../../tools/ci/run_test_lane.sh) exposes `unit` and `ui-navigation`, not a performance lane. The five mixed entry points and hatch timing currently run with regression. `SkyAware_All_Tests`, UI plans, scheme default, Debug and target structure remain unchanged by this report.

1. **#766:** modify only the four measurement-owner Swift files. Add the five untimed R entry points proposed above, sharing existing private operations; retain the six original measurement entry points, repetitions and reports for P. No new target or broad reorganization. Preserve repeated correctness where it tests consistency (two observations), rather than retaining nine/ten timing runs in R. Keep the gated render and all other correctness tests unchanged.
2. **#767:** add the optional performance plan and local runner invocation; update scheme plan references only as needed to expose it. Default R excludes exactly the six measurement entry points after the five R replacements are verified. P positively selects exactly those six timing entry points across both frameworks. Do not select the whole `RiskPolygonOverlayTests` suite or whole accepted-update file. Keep existing diagnostics policy and parallel setting unless separately authorized evidence warrants changing them.
3. **#768:** enforce the selection/skip contract and reconcile Cloud documentation against the actual workflow. Do not hardcode historical total counts as a completeness gate.

Swift Testing `@Test` identifiers and parameterized runs differ from XCTest `test...` method identifiers. Plan and CLI selection operate on discovered identifiers, not filenames or display labels; an XCTest metrics-only filter would miss manual Swift Testing measurements and manual-clock XCTest cases. An `@Test` trait alone cannot select XCTest methods. Suite-level selection/exclusion is too coarse where timing and correctness share an owner. Do not hand-author runtime identifiers from this table: enumerate with the installed Xcode, select the discovered method identifiers, and verify actual execution after changing plans. Parameterized tests must keep every argument run; logical totals and expanded executions are different quantities.
